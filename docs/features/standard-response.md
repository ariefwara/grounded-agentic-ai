# Standard Response

When a user sends a request to Grounded Agentic AI, the system does not attempt to answer everything. It is designed to respond only when every required condition is met. When a request cannot be answered or processed, the system returns a **standard response** — a pre-configured, approved message that does not improvise, invent policy, or create new wording.

## Why a Standard Response Exists

Most chatbots attempt to answer any question, even when they lack the right information or authority. This creates risk: the AI may guess, make up policy, disclose information it should not, or promise actions it cannot deliver.

Grounded Agentic AI avoids this by treating unanswered requests as a deliberate outcome, not a failure. The standard response is the system's way of saying "I cannot process this request" without creating new content.

## When the Standard Response Is Used

The system uses a standard response in several situations:

- **The request does not match an approved question or intent.** If the user asks something the business has not configured the system to handle, the AI must not answer freely, search for a workaround, or invent policy. It returns the standard response.

- **The user is not eligible for the information.** Even if the question matches an approved intent, the user may not have the right identity, verification level, or relationship to the account. The system does not disclose the information. It returns the standard response.

- **The action is not allowed.** If the request includes an action that is not predefined, not configured for this user, or not permitted on this channel, the system does not execute the action, does not pretend the action was executed, and does not promise the action will succeed. It returns the standard response.

- **An intermediate or final response fails a gate check.** Every response step — retrieval, draft answer, action call — is evaluated before it proceeds. If any gate fails, the system drops the response. If retry is allowed and fails within the configured limit, the system returns the standard response.

## What the Standard Response Is Not

The standard response is not a denial generated by the AI. It is not a polite refusal the model creates on the spot. It is a configured, approved message that the business controls.

The system does not:

- Answer freely from general model knowledge.
- Search for a workaround to answer the question.
- Invent policy or create a new denial wording.
- Improvise a reason for not answering.

The standard response is the same for every situation where the system cannot proceed — unless the business configures different standard responses for different scenarios.

## How the Standard Response Is Selected

The system selects the standard response from a set of approved options. These can include:

- A single default message for all unanswered requests.
- Different messages for different scenarios (e.g., unmatched question vs. ineligible user).
- Channel-specific messages (e.g., different wording for web chat vs. email).
- Audience-specific messages (e.g., customers vs. employees).

The AI does not create the wording. It selects the configured standard response and may adapt the wording only if the meaning stays exactly the same, the style is correct, and no unsupported claim or commitment is added.

## Practical Consequence

The standard response feature means the business controls what happens when the AI cannot answer. There is no risk of the model inventing a reason, making a false promise, or disclosing information it should not. The system either answers within its boundaries or returns a safe, predictable message.

This is not a limitation. It is the mechanism that keeps the system from becoming a freeform chatbot that answers anything — and from creating the business risk that comes with that freedom.
